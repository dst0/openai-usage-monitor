# 2026-09-28 — A shell test's rewritten fakes fall through to the real command when the script changes spelling

- **Status:** Resolved
- **Task/context:** Branch `ci/run-shell-tests` added every `tests/*.sh` script to the required CI jobs. Each script was first checked for hermeticity on the development Mac. `tests/install_monitor_process_guard.sh` and `tests/install_restart_worker_wait.sh` fake system commands the same way: they copy the production helper and rewrite absolute paths with `sed` (`/bin/ps`, `/bin/kill`, `/bin/launchctl`, `/bin/sleep`) to point at fakes in a temporary directory.
- **Unexpected observation or failure:** The rewrite only replaces the spelling it names. If the production helper switches to the `kill` builtin, a bare `launchctl`, or another path, the copy runs the real command and the test gives no warning. The process-guard test's last case then sends a real `SIGTERM` to PID 4242, whatever process has that PID on the machine running the test.
- **Evidence:**
  - Mutation in a scratch copy: `/bin/kill -TERM "${pid}"` in `scripts/install_monitor_process_guard.sh` changed to `kill -TERM "${pid}"`. The unchanged test (from `88d3cec`) got as far as the builtin and printed `kill: (4242) - No such process`. PID 4242 did not exist, which was checked first, so nothing was signalled.
  - Mutation: `/bin/launchctl list` in `scripts/install_launchd_helpers.sh` changed to a bare `launchctl list`. Under a `sandbox-exec` profile that kills any process executing `/bin/launchctl`, the unchanged test failed with `restart worker state could not be verified`, because the real `launchctl` had been executed and killed. Outside the sandbox it would have queried the real launchd.
  - Mutation: `/bin/sleep 0.1` in `scripts/wait_for_restart_worker.sh` changed to a bare `sleep 0.1`. The unchanged test runs the real `sleep`; this is harmless, but it shows the same bypass.
  - Before these checks, all six scripts that had run only locally passed under a profile that kills a process on any write outside the scratch `TMPDIR` or the Clang module cache, on access to `~/.codex`, `~/.local/bin`, `~/Applications`, `~/Library/LaunchAgents`, or the installed ChatGPT or Monitor bundle, and on execution of `launchctl`, `kill`, `osascript`, `open`, `defaults`, `pkill`, `killall`, or `sfltool`. None left files in the scratch `TMPDIR`. So the current scripts are hermetic; the gap only opens when a production helper changes.
- **Approaches tried:**
  - **Attempt:** Rely on the kill-on-access sandbox to catch a test that reaches a real command.
    - **Outcome:** Did not work.
    - **Why:** It only checks the machine it runs on, and only when someone runs it. It cannot stop a builtin `kill`, which executes nothing. CI runs the tests without it.
  - **Attempt:** After rewriting, grep each copy's non-comment lines for the command words (`kill`, `pkill`, `killall`, `ps`; `launchctl`, `sleep`), remove the fake paths, and fail if any word remains. This follows the guard `tests/log_permissions_and_uninstall.sh` already keeps for its uninstaller copy.
    - **Outcome:** Partial.
    - **Why:** The check runs before the copy is sourced or executed, on every machine, and does not depend on which PIDs or launchd jobs exist. An adversarial review found gaps. A `${KILL:-kill}` default slipped past the word boundary. A `source` of an unrewritten sibling file would run real commands the guard never sees. And nothing proved the guard could fail at all, since the clean copies never trip it.
  - **Attempt:** Treat `-` as a word boundary, extend the word list to other process and launchd commands (`pgrep`, `lsappinfo`, `launchctl`, `osascript`, `open`), reject any `source` or `.` line except the wait script's own helper copy, and run each guard first on sample bad lines, which must be rejected, and on fake paths and comments, which must pass. Also require a plain-character `TMPDIR`, because the fake paths are spliced into `sed` programs. `tests/install_bundle_swap.sh`, which sources the real transactional helper, gets the same kind of self-checked guard against `/Applications`, `HOME`, `~`, and sourced files.
    - **Outcome:** Worked.
    - **Why:** A broken or mistyped guard now fails its own sample lines instead of passing silently.
- **Root cause:** A path rewrite is an allowlist of spellings. A new spelling of the same command bypasses it without an error.
- **Resolution:** Both tests now fail before running the copy if a real process or launchd command, or an unrewritten sourced file, can still be reached. The failure names the line. The three mutations above (builtin `kill`, bare `launchctl`, bare `sleep`) each fail with that message, and the unmodified scripts pass.
- **Verification:** The three tests pass alone and under the kill-on-access sandbox, with a scratch `TMPDIR` that is empty afterwards. Each of the three mutations fails with the new guard message before anything is sourced or executed. Each guard rejects its sample bad lines on every run.
- **Prevention/follow-up:**
  - `AGENTS.md` (CI enforcement) requires every command rewrite in a shell test to have such a guard. The required CI jobs now run all three tests on every pull request, which closes the follow-up recorded in [2026-09-28 — Uninstall kept a killed install's staging, and its test never ran in CI](2026-09-28-uninstall-kept-killed-install-staging.md).
  - Still open: `tests/log_permissions_and_uninstall.sh` runs its uninstaller copy with the real `/bin/ps`, `/bin/kill`, and `/bin/sleep`. It signals only processes whose command line names its own temporary tree, but it reads the live process table.
- **Reusable learning:** When a test fakes a command by rewriting its path in a copy of production code, also assert that the copy names no other spelling of that command. Otherwise a harmless refactor of the production code turns the test into one that acts on the real system.

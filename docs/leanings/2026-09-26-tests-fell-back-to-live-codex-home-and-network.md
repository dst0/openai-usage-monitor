# 2026-09-26 — Tests fell back to the live Codex home and reached the network

- **Status:** Resolved
- **Task/context:** Making every `codex-switcher` unit test hermetic with respect to `CODEX_HOME` and the network, following an adversarial review of test isolation.
- **Unexpected observation or failure:** Several tests "cleaned up" with `std::env::remove_var("CODEX_HOME")`, and `distribution::test_helper::TestEnv` never restored the variable at all. `storage::codex_home()` treats an unset value as the live `~/.codex`, so any later test that called code resolving the home (the logger, for example) touched the owner's real state. Four tests also sent live requests to chatgpt.com and the OAuth token endpoint with fake tokens. Every one of these tests still passed.
- **Evidence:** Each unit test was run alone under `sandbox-exec` with a profile that kills the process on any non-loopback connection or any access to `~/.codex`:
  ```
  (version 1)
  (allow default)
  (deny network-outbound (remote ip) (with send-signal SIGKILL))
  (allow network-outbound (remote ip "localhost:*"))
  (deny file-read* file-write* (subpath "/Users/<owner>/.codex") (with send-signal SIGKILL))
  ```
  Before the change, five tests were killed. `test_detect_in_progress_live` read the live home. `running_desktop_recovery_uses_windowserver_and_continues_without_visible_window` wrote its `RECOVERY_BANNER_UNAVAILABLE` warning into the live `switcher.log`. `test_reset_account_in_file_success`, `test_reset_account_in_file_desktop_app_alias`, and `test_rename_account_updates_nickname` reached the network. After the change, none are killed, whether run alone or as the full parallel suite.
- **Approaches tried:**
  - **Attempt:** Run the suite under a sandbox that only denies access, without killing.
    - **Outcome:** Did not work as a detector.
    - **Why:** The offending paths swallow errors (`catch_unwind`, `let _ =`, `unwrap_or_default`), so a denied request or read simply took an error branch and the test still passed. `(with send-signal SIGKILL)` makes each violation fatal and attributable. Loopback must stay allowed because `quota.test.rs` uses a local fixture server.
  - **Attempt:** Make `codex_home()` panic in test builds when `CODEX_HOME` is unset, and rely on that alone.
    - **Outcome:** Partial.
    - **Why:** `CODEX_HOME` is process-wide. If a test leaks a temporary value, an unguarded test borrows that stale home instead of panicking, and in a parallel run it can also borrow another test's live guard. The panic is deterministic only when every mutation restores the prior value. That is why a source scan now forbids direct `set_var`/`remove_var` of `CODEX_HOME`, and why unguarded callers were found with `--test-threads=1`.
  - **Attempt:** In test builds, reject only an unset `CODEX_HOME` or one that textually names `$HOME/.codex`, and have the guard restore the previous value.
    - **Outcome:** Did not work well enough.
    - **Why:** The adversarial critic showed three gaps. A developer's exported `CODEX_HOME` pointing at real data was restored after every test and then accepted. A symlink or case variant of `~/.codex` passed the check. An unguarded call on another thread silently used the active guard's home. Mutating the guard to lock a different mutex, or to stop restoring, left every guard test green.
  - **Attempt:** A shared RAII guard (`storage::test_codex_home::TestCodexHome`) that holds `TEST_CODEX_HOME_MUTEX` and recovers and clears a poisoned lock. It creates a fresh canonical temporary directory and records that home and its owning thread. It clears `CODEX_HOME` while unwinding and panics on nesting. In test builds, `codex_home()` accepts only the recorded home, and only on the owning thread.
    - **Outcome:** Worked.
    - **Why:** `Drop` runs during unwinding, so a failed assertion can no longer leak a value. Any foreign value (live, inherited, symlinked, or another test's) and any unguarded thread now panics every time. A cross-thread test proves that a second guard waits for the first and then finds `CODEX_HOME` already cleared; both mutations above now fail it. Clearing the poison stops one failure from cascading into every later `.lock().unwrap()`. `TestEnv` now owns a guard, so its callers must no longer lock the mutex themselves, because the mutex is not reentrant.
  - **Attempt:** Inject the quota-cache refresher into `reset_account_in_file`, and the status refresh into `rename_account_with`.
    - **Outcome:** Worked.
    - **Why:** Production passes `quota::update_account_quota_cache` and `daemon::refresh_quotas_and_status`. Tests pass recording fakes that also verify ordering: the refresh runs after the credit decrement or after the rename is saved.
- **Root cause:** `remove_var` was treated as restoring the environment, but for `CODEX_HOME` it selects the live default. The live refreshes ran inside `catch_unwind` or behind discarded `Result`s that were meant to "ignore failure in offline / test", which hid real requests. - **Resolution:** `codex_home()` moved to `storage/codex_home_resolver.rs`. Production resolution is unchanged, including `std::env::var`, which keeps it aligned with Codex. In test builds it panics unless `CODEX_HOME` is the calling thread's guard home. Every test that changed the variable by hand now uses `TestCodexHome`. `tests/enforce_codex_home_isolation.rs` rejects direct `CODEX_HOME` mutation outside the guard. The two network seams are injected. The live detection smoke test, which asserted nothing, was removed.
- **Verification:** `cargo test` in `codex-switcher` passes: 300 unit tests plus 16 in the integration binaries after rebasing onto main at a8ab321, whose 22 new mutex-locking tests were migrated to the guard as well. The unit suite also passes serially under the enforcing resolver. Under the kill-on-violation sandbox, every unit test run alone passes. The full suite also passed repeatedly there, apart from the pre-existing rotation flake described below; that failure was an assertion failure, not a sandbox kill. The resolver and source-scan regression tests failed before the fix. The guard tests cover restoration after a panic and a poisoned mutex.
- **Prevention/follow-up:** AGENTS.md (Test Quality & Adversarial Review) now names the guard, the test-build panic, the source scan, and injected refreshes. A separate pre-existing flake is still open: `ownerless_prune_rotates_one_rollout_scan_per_pass` shares the global `NEXT_OWNERLESS_PROBE` cursor with concurrent tests. It failed 3 of 30 runs on unmodified `main` too, and it is not caused by `CODEX_HOME`. - **Reusable learning:** For a process-wide variable whose unset value means "live state", only restore-on-drop is a valid cleanup, never `remove_var`. To audit hermeticity, make each violation fatal (sandbox SIGKILL or a test-build panic) and run tests one at a time. A swallowed error cannot be seen by the test that caused it.

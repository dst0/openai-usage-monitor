# 2026-09-27 — Cargo `--locked` scan failed open on comments and indirect spellings

- **Status:** Partial
- **Task/context:** Adversarial review of the new `--locked` policy rule (`codex-switcher/tests/ci_workflow_policy/locked_cargo.rs`) added while committing `Cargo.lock` ([2026-09-27-ignored-cargo-lock-left-builds-unpinned.md](2026-09-27-ignored-cargo-lock-left-builds-unpinned.md)).
- **Unexpected observation or failure:** The first version passed unlocked cargo commands. It cut comments at the first ` #`, so a quoted `#` hid the command after it and a tab before `#` kept comment text, including a `--locked` written only in the comment. It also matched only the literal word `cargo` or a path ending in `/cargo`. The git helper answered "not ignored" for a path git could not see, and accepted a symlink as the committed lockfile.
- **Evidence:** On the first version, each of these reported no violation: `echo "Building #1" && cargo build`, `run: echo "step #2"; cargo test`, `cargo build<TAB># --locked`, `\cargo build`, `$(command -v cargo) build`, and `$CARGO build`. `git ls-files --cached --others --ignored --exclude-per-directory=.gitignore -- <path>` prints nothing for a path in neither the index nor the working tree, which the helper read as "not ignored". `git ls-tree` reports a symlink as type `blob` with mode `120000`. The live `scripts/install.sh` (an `osascript -e "…"` program) and `scripts/uninstall.sh` (two `awk '…'` programs) contain quoted strings that span lines.
- **Approaches tried:**
  - **Attempt:** Report every line that ends inside an open quote as unreadable.
    - **Outcome:** Did not work
    - **Why:** It rejects the multi-line quoted programs in the live scripts.
  - **Attempt:** Carry the quote state across lines, joining lines only on an unquoted trailing `\`, and report a quote still open at the end of the file.
    - **Outcome:** Worked
    - **Why:** Quote state only decides where comments start, so an error in it can only expose more text to the scan. Keeping lines apart means a `--locked` on a later line never counts toward an earlier command, and a quote that never closes is reported.
  - **Attempt:** Treat any word naming a `CARGO` variable as cargo.
    - **Outcome:** Did not work
    - **Why:** `echo "$CARGO_HOME"` and `rm -rf "${CARGO_TARGET_DIR}"` would be reported. Such a variable counts only as the command word (after assignments, options, wrappers such as `env`, and keywords such as `if`). A `$(…)` or backtick lookup of cargo stands for `cargo` anywhere.
- **Root cause:** A line scan that splits on text patterns and ignores the shell's quoting and quote-removal rules.
- **Resolution:** `shell_lines.rs` reads command lines with quote-aware comments, continuations that a comment ends, and unterminated-quote reporting. `locked_cargo.rs` removes quotes and backslashes from words as the shell does, substitutes cargo lookups, and treats `CARGO` variables in the command position as cargo. `git_repo.rs` returns an error for a path it cannot see and requires mode `100644` or `100755`. The module doc lists the remaining limits.
- **Verification:** Each input above is now reported; a probe of the first version, run on a throwaway merge, returned no violation for each. The symlink and unseen-path cases are covered by `git_repo.test.rs`. A mutation of each new condition fails at least one test (listed in the linked learning). The live workflows and all tracked scripts still pass, including the multi-line quoted programs.
- **Prevention/follow-up:** Known misses, which the CI-only lockfile check partly backs up: commands built at run time (`eval "$cmd"`, cargo aliases, `${{ matrix.cmd }}`), `bash -c "cargo build" --locked`, a `\` continuation into the next YAML key, lookup words as option values (`sudo -u type cargo build`), and third-party actions that run cargo. Known false positives, which fail closed: prose containing a bare lowercase `cargo` word, paths ending in `/cargo` used as data, `cargo -vV`, `cargo --list`, a redirect attached to a flag, and `--locked` after `2>&1` or `&>`.
- **Reusable learning:** A policy scan of shell text must handle quoting before it decides what is a comment or a word: carry quote state across lines, remove quotes as the shell does, and report text it cannot delimit. Any git query that cannot see a path must return an error, not a default answer.

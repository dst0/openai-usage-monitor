# 2026-09-27 — A fake IPC router's read timeout made a dispatch test flaky

- **Status:** Resolved
- **Task/context:** Stabilising `recovery::target_dispatch_tests::already_unpaused_queue_sends_one_owner_routed_wake_before_consuming_checkpoint` in `codex-switcher`, which earlier reviews saw fail intermittently with "Broken pipe" on a loaded machine.
- **Unexpected observation or failure:** The test failed with `error=Some("Broken pipe (os error 32)"), routed=None, dispatched=true, consumed=true`. The client had marked the checkpoint dispatched, but its wake request never reached the fake Desktop router. A second, rarer failure under load reported `Invalid argument (os error 22)` with `routed=Some(true)`: the router had received and answered the wake. That second mode is recorded separately in [the XNU setsockopt learning](2026-09-27-xnu-setsockopt-einval-after-peer-close.md).
- **Evidence:**
  - At load average 64 on a 10-core Mac, 12 parallel runs of the unmodified test failed 4 of 60 times, every failure with `Broken pipe`. A later batch at load average 92 failed 2 of 60 times with `Invalid argument`.
  - The router thread read each request with `set_read_timeout(500 ms)` and returned `None` on any read error, dropping its socket. Between answering owner discovery and receiving the wake, `dispatch_if_needed` revalidates the queue and rollout three times. That is six `/usr/bin/sqlite3` spawns, plus a rollout scan, two banner-gate callbacks, and an fsynced manifest rename.
  - A variant whose first banner-gate callback sleeps 750 ms failed 5 of 5 runs with the identical `Broken pipe` message. Production banner startup alone can take seconds.
- **Approaches tried:**
  - **Attempt:** Raise the router's read timeout (considered, not implemented).
    - **Outcome:** Rejected.
    - **Why:** It only moves the threshold. The negative tests used the same timeout as their "no request was sent" detector, so a longer timeout slows them, and any timeout lets a late, wrongly dispatched request pass unseen: the router has already stopped listening, the request fails with `EPIPE`, and the test counts the `Err` as a refusal.
  - **Attempt:** Replace every hand-rolled router with `recovery::test_desktop_router::TestDesktopRouter`. It answers scripted requests on its own thread and keeps its end open until the client hangs up. `finish(client)` drops the client and returns every request the router received.
    - **Outcome:** Worked.
    - **Why:** A missing request is now observed as client EOF, which is deterministic. Slow production work between two requests cannot make the router leave early. The tests now assert the exact request sequence, so "exactly one wake" and "no request after an account change" are checked directly.
- **Root cause:** The fake peer used a wall-clock read timeout both as a hang guard and as its signal that no further request would arrive. Production work between two requests, sized for multi-second banner and SQLite waits, can outlast 500 ms on a loaded machine. The router then closed, and the client's next write failed with `EPIPE`.
- **Resolution:** `TestDesktopRouter` replaces the three routers in `target_dispatch.test.rs` and the multi-window routing test in `ipc_protocol.test.rs`. `unpaused_queue_wake_survives_a_slow_banner_gate` keeps the 750 ms reproduction as a permanent regression test.
- **Verification:** The slow-gate test failed 5 of 5 times on the old harness and passes on the new one. In an A/B run, the base-commit binary and the fixed binary each ran the formerly flaky test 150 times at 20-way parallelism, at the same time, while four full suites ran as extra load. The base binary failed 5 times (4 `Broken pipe`, 1 `Invalid argument`); the fixed binary failed none. On its own, the fixed test also passed 100 of 100 runs at 16-way parallelism with a load average of about 200. After review fixes and a rebase onto main at 6792b6d, a targeted set of 20 dispatch, router, and IPC tests passed 150 of 150 runs at 24-way parallelism beside 20 CPU-bound processes (load average rising to 57). `cargo test --locked` passed three consecutive times.
- **Prevention/follow-up:** AGENTS.md (Test Quality) now requires fake IPC peers to stay connected until the client hangs up and to detect a missing request from EOF. `quota.test.rs` still uses a 2 s timeout on its loopback HTTP fixture; the client sends at once there, and no flake has been observed.
- **Reusable learning:** A fake peer must never infer "no request" from a read timeout. Keep the connection open until the client hangs up and read to EOF; production code between two requests can outlast any fixed test timeout.

# 2026-09-27 — A synthesized Desktop shortcut needs keymap, delivery, and focus proof

- **Status:** Partial
- **Task/context:** Reviewing and finishing the Codex-authored `cxi window probe-tasks --allow-focus-and-clipboard` diagnostic (`scripts/CodexWindowTaskProbe*.swift`) before publication. The probe focuses each ChatGPT window and synthesizes Copy deeplink to learn whether every window exposes a distinct selected task.
- **Unexpected observation or failure:** The prototype treated Cmd+Opt+L as if it were a function call. It posted the keystroke at the HID event tap, trusted `NSWorkspace.frontmostApplication` after one fixed 80 ms sleep, assumed the shortcut always meant Copy deeplink, and read the clipboard text after reading the change count, so a write between those two reads could be accepted. An adversarial review of the first hardening pass then showed that the key's meaning also depends on the keyboard layout, the ChatGPT build, macOS App Shortcuts, and which Codex home ChatGPT reads, and that one of the new tests was vacuous.
- **Evidence:**
  - Read-only inspection of the bundled JavaScript of installed ChatGPT 26.924.20706 (`com.openai.codex`; no process launched, no window touched): the `copyDeeplink` command has `defaultKeybindings` `CmdOrCtrl+Alt+L` and is a hidden menu item (`visible: false`, `acceleratorWorksWhenHidden: true`). Its click handler sends `copy-deeplink` to `BrowserWindow.getFocusedWindow()` and otherwise falls back to a function that makes the primary window visible. A thread view copies `codex://threads/<id>` only when a conversation is selected; a plugin page copies a plugin link instead.
  - Keybinding overrides are read from `join(CODEX_HOME ?? ~/.codex, "keybindings.json")`, a JSON array of `{command, key}`, and re-read whenever a Desktop window gains focus. A missing, blank, or unparsable file means defaults. The in-app editor removes a reassigned accelerator from the command that held it; a hand-edited file can leave the default on both commands.
  - Translating key code 37 with Command held through `UCKeyTranslate` gives `l` on U.S. and Dvorak - QWERTY Command, `n` on Dvorak, and `i` on Colemak (`tests/CodexWindowTaskProbeTests.swift`). The review reported `z` and `c` on the one-handed Dvorak layouts and `l` on the other 260 bundled layouts. Hidden Desktop commands with Cmd+Opt defaults on other letters exist, so another layout could select one of them.
  - The macOS 15.4 SDK documents that the general pasteboard asks the user upon programmatic access by default (`NSPasteboardAccessBehavior`).
  - The probe was not run live in this work.
- **Approaches tried:**
  - **Attempt:** Post the shortcut at the HID tap after a focus check.
    - **Outcome:** Did not work.
    - **Why:** Rejected on review: a focus change between the check and the post sends Cmd+Opt+L to whichever app is frontmost, which may give it an unrelated meaning.
  - **Attempt:** Use `NSWorkspace.frontmostApplication` as the focus witness inside the helper.
    - **Outcome:** Did not work.
    - **Why:** Rejected on review: that property is refreshed by workspace notifications, which a command-line helper without a run loop never processes, so it can stay stale. Not reproduced live, because running the probe was out of bounds.
  - **Attempt:** Invoke Copy deeplink without a keystroke, through Accessibility.
    - **Outcome:** Did not work.
    - **Why:** Hidden menu items are normally not exposed to Accessibility (inferred, not observed). The renderer's visible "Copy app link" item in the thread menu would need AX navigation of web content with localized labels, a larger and less predictable UI interaction.
  - **Attempt:** Parse `keybindings.json` and allow overrides that do not touch Copy deeplink or Cmd+Opt+L.
    - **Outcome:** Did not work.
    - **Why:** Rejected: accelerator spelling equivalence and default-removal rules are Desktop internals, and a mistake would run a different command, such as archiving a task, in every window.
  - **Attempt:** First hardening pass: refuse any keymap override; post the event only to the verified PID; read focus live from Accessibility, polled for up to 1 s and rechecked after each copy; refuse minimized windows and missing Accessibility or event-posting access before any visible change; require one clipboard write whose change count is unchanged across the text read; hold the switch/recovery operation lock for the whole run.
    - **Outcome:** Partial.
    - **Why:** The review found gaps: no layout, build, App Shortcut, or pasteboard-prompt check; the keymap was read from the CLI's `CODEX_HOME`, which may differ from ChatGPT's; the Swift sequencing had no tests; and the lock-lifetime test still passed when the lock was released before the helper ran.
  - **Attempt:** Second pass: gate on ChatGPT 26.924.20706, a layout where key 37 types `l` with Command (checked again before each post), no `NSUserKeyEquivalents` entry on Cmd+Opt+L, silent pasteboard reads, and the default Codex home; skip concealed or transient pasteboard contents without reading them; recheck the keymap after the run; mark failures after the first focus; move the sequencing into `WindowTaskProbe` behind `WindowTaskProbeSystem` and test it with a scripted fake; prove the lock lifetime with a marker the fake helper writes.
    - **Outcome:** Partial.
    - **Why:** Each check is covered by hermetic tests, and mutating each one makes a test fail. Live delivery is still unproven: macOS cooperative activation, pid-targeted delivery to Electron accelerators, the change count updating without a run loop, and Chromium's pasteboard write count have not been observed on the installed Desktop.
- **Root cause:** A keystroke's meaning comes from the user's keymap, App Shortcuts, keyboard layout, and the Desktop build, and its target comes from the application's focused-window fallback and from HID focus at delivery time. The prototype proved none of them.
- **Resolution:** `WindowTaskProbeService` checks the opt-in flag, the Desktop Codex home, the operation lock, the keymap, and a single ChatGPT process before it resolves the helper, and rechecks the keymap afterwards. `CopyDeeplinkKeymapService` accepts only an absent, blank, or `[]` regular file. The helper's `WindowTaskProbe` refuses every unmet precondition before its first focus request, posts only to the PID, polls Accessibility focus, and validates the clipboard with a confirming change count. The CLI names fixed failure codes, says when a failure followed a focus change, and never echoes other helper output.
- **Verification:** Rust unit tests for the service order, the lock lifetime (a marker written by the fake helper must exist when the lock is released), the Desktop home, keymap acceptance, refusal, and edits during the run, response and failure-code validation, a Swift/Rust failure-code and window-limit drift check, and CLI parsing, all with temporary fake helpers and homes. Each new unit test also passes alone under a kill-on-live-access `sandbox-exec` profile. `tests/enforce_task_probe_isolation.rs` scans the repository for callers. Swift tests cover link validation, one-to-one frame mapping, the build, App Shortcut, and pasteboard policies, key translation on bundled layouts, and the probe sequence against a scripted fake. Mutating the lock lifetime, the check order, the keymap recheck, the nested response check, the after-focus marker, the pre-post focus and layout rechecks, the count/text/count read order, the type check before a read, or the post-copy recheck makes a test fail.
- **Prevention/follow-up:** The owner should run the probe once on a two-window Desktop with a default keymap, a U.S.-style layout, and pasteboard access set to always allow, and record the result in a new linked learning. After each ChatGPT update, re-inspect the `copyDeeplink` binding and the keymap path before changing `verifiedDesktopVersion`.
- **Reusable learning:** A synthesized shortcut is attributable only when its binding, the keyboard layout, its recipient process, and the focused target are each proven at delivery time; otherwise refuse before any visible change.

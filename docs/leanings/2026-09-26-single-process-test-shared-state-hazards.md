# 2026-09-26 — Shared test state in the single-process test binary

- **Status:** Resolved
- **Task/context:** A review of the ownerless-rotation flake fix ([2026-09-26-process-global-rotation-cursor-flaky-test.md](2026-09-26-process-global-rotation-cursor-flaky-test.md)) looked for other process-wide state in `codex-switcher`. The crate has one binary (`codex-mon`), so every unit test runs in the same process and shares its statics, environment, and locks. The work was first done on main at a8ab321 and then rebased onto main at 0b45207, after #15 and #14 had merged.
- **Unexpected observation or failure:** The review found hazards that had not yet failed a run:
  - The checkpoint scan cache was a process-global `HashMap` capped at 128 entries. When full, it evicted `keys().next()`, whose order depends on `RandomState`. The eviction branch never ran in tests, and a test that filled the shared cache would have evicted other tests' entries at random. #15 kept that cache and added a second one with the same policy for snapshot confirmations. It also added the per-home rotation map, which uses the same policy (see the rotation entry).
  - The cache inserted a new entry, evicting another if full, before the new scan ran, so a probe that then failed still cost another checkpoint its progress.
  - Tests locked `TEST_CODEX_HOME_MUTEX` with `.lock().unwrap()` in some places and recovered poison in others, and `test_detect_in_progress_live` and a banner test could resolve the live `~/.codex`. [2026-09-26-tests-fell-back-to-live-codex-home-and-network.md](2026-09-26-tests-fell-back-to-live-codex-home-and-network.md) (#14) resolved those with `TestCodexHome`.
- **Evidence:** On a8ab321, an instrumented full run made 31 cache inserts and 0 evictions. A test that poisoned the mutex made 5 unrelated `setup::tests` fail with `PoisonError` under `--test-threads=1`. A least-recently-probed eviction test failed 12 of 21 runs against an injected cache that kept random eviction. On 0b45207 plus this branch, an instrumented full run stored 40 distinct checkpoint keys in the shared registry (85 stores). No cache held more than 39 entries, so nothing was evicted.
- **Approaches tried:**
  - **Attempt:** Keep the global cache and add an eviction test that uses unique paths.
    - **Outcome:** Rejected.
    - **Why:** To reach eviction, the test must fill the shared cache, which evicts other tests' cursors at random.
  - **Attempt:** Inject only the capacity and keep one global map.
    - **Outcome:** Rejected.
    - **Why:** Tests would still share entries, and eviction order would stay random.
  - **Attempt:** Move both caches into `CheckpointScanRegistry`, which `ManifestPruneService` borrows next to the rotation. Keep the process-wide instance in `CheckpointScanRegistry::shared()` for the free functions in `restart_checkpoint_service.rs`. Order entries by probe, take an entry out for a probe, and put it back as the most recent only after the probe succeeds.
    - **Outcome:** Worked after a review fix.
    - **Why:** Each registry test owns its registry, and eviction order depends only on probe order. In production, the evicted entry is usually a target that already left the journal, not an arbitrary long-rollout cursor whose progress would be lost. An adversarial review found that a confirmation whose scan failed was still put back, evicting a completed confirmation and holding a slot that proved nothing; `CheckpointConfirmation::scan_with_budget` now returns the error so the registry drops that entry. An append cursor that saw a malformed or oversized record is still kept on purpose, because it reports no evidence and a rescan would find the same record.
  - **Attempt:** Make the `CODEX_HOME` test mutex poison-tolerant at every call site.
    - **Outcome:** Superseded.
    - **Why:** #14's `TestCodexHome` recovers and clears poison for every holder. This branch made the mutex private to that module, so the compiler rejects a direct lock.
- **Root cause:** Process-wide test state (caches, a cursor map, a mutex, and an environment variable) was reachable from tests that did not own it. Random-order eviction also made the caches' bounded behavior impossible to test deterministically.
- **Resolution:** Added `codex-switcher/src/recovery/checkpoint_scan_registry.rs`. `ManifestPruneService` takes the registry and the rotation by reference, and the production wrappers call `ManifestPruneService::shared()`.
- **Verification:** `checkpoint_scan_registry.test.rs` covers least-recently-probed eviction for both caches, cursor reuse (a partially scanned cursor keeps accumulating after another checkpoint enters a full registry, while an evicted one restarts), filling the confirmation cache without touching append cursors, a single-entry registry, slot reuse after rollout replacement, a failed append probe or confirmation dropping only its own entry and never evicting another, a changed or partial snapshot not counting as current, isolation between registries, and zero capacity. Seven temporary mutations each failed a test: evicting the most recent entry, evicting before scanning, keeping a cursor after a failed probe, keeping a failed confirmation, ignoring whether a confirmation completed, never reusing a cached cursor, and letting a confirmation clear the append cursors.
  An adversarial review also showed that no test caught a production prune pass building its own rotation and registry: `prune_ineligible_targets` repeated the `shared()` call that only its test twin `prune_ineligible_targets_with` exercised. Production now delegates to `prune_ineligible_targets_with`, and building fresh state there fails `prune_rotates_one_ownerless_rollout_scan_per_pass` and `ownerless_rotation_is_fair_when_other_homes_are_probed`. A second review showed that fresh state built in `prune_ineligible_targets` itself still passed every test, so `production_prune_passes_share_one_rotation` now calls it three times over a seeded `state_5.sqlite` and requires all three rollouts to be scanned. In an instrumented full run on 0b45207 the shared registry peaked at 39 of 128 entries and the rotation at 14 of 128 homes, so tests that go through the shared instance with their own home and rollout paths do not evict each other today.
- **Prevention/follow-up:** AGENTS.md requires tests to own rotating and bounded-cache state and to keep eviction deterministic. The checkpoint-scan-cost contract in AGENTS.md and the recovery section of CODEX.md now name the least-recently-probed eviction. Known limitation: if more than 128 cold targets are probed round-robin and each has more than 16 MiB left to scan, LRU evicts every cursor before its next turn, so none finishes. Random eviction would let some finish, though at random. The recovery journal holds only four hours of tasks, so this is far outside realistic use. If it ever matters, prune registry entries whose target left the journal instead of raising the capacity.
- **Reusable learning:** In a single-process test binary, treat every static, environment variable, and shared lock as shared across tests. Inject caches and cursors, give bounded caches a deterministic eviction order, evict only after the new entry has proved useful, make shared test locks poison-tolerant by construction, and never let a test fall back to the developer's real application data.

# 2026-09-28 — Enabled privacy row did not authorize the launchd helper

- **Status:** Partial
- **Task/context:** Live installation check after merging PR #49 on macOS 27.2, with ChatGPT 26.924.22138 and automatic switching disabled.
- **Unexpected observation or failure:** The installed `codex-window-restore` read the current ChatGPT window interactively but was denied Accessibility as a one-shot launchd job, although System Settings displayed an enabled row for it.
- **Evidence:** The installation from merge commit `1f63736` signed `codex-mon` and the helper ad hoc. An interactive `count-standard-windows` returned one standard window with no ambiguous windows. The same exact helper, ChatGPT PID, and birth identity under `launchctl submit` returned `WINDOW_ACCESSIBILITY_DENIED`, before reading window data. Privacy & Security > Device Control and Data Access showed enabled `codex-mon` and `codex-window-restore` rows; Screen & System Audio Recording showed an enabled `codex-mon` row but no helper row. ChatGPT kept its original PID; the probe sent no account-switch or recovery request.
- **Approaches tried:**
  - **Attempt:** Treat an enabled System Settings row and an interactive inventory as sufficient. **Outcome:** Did not work. **Why:** The launchd inventory still failed before any Desktop signal.
  - **Attempt:** Use the new fixed, read-only launchd preflight. **Outcome:** Worked diagnostically. **Why:** It identified the missing background Accessibility authorization without prompting, restarting ChatGPT, or changing credentials.
  - **Attempt:** Regrant current executables or use a stable signing identity. **Outcome:** Pending. **Why:** These change security-sensitive access; no valid code-signing identity is installed, and the needed user approval has not yet been given.
- **Root cause:** The current helper is not trusted as an Accessibility client in the launchd context. A stale privacy grant after rebuilding ad hoc signed code is consistent with [Apple's designated-requirement explanation](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements), but the exact TCC record and attribution have not been verified. [Apple defines `AXIsProcessTrusted()` as a check of the current process](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted).
- **Resolution:** Keep automatic switching disabled and retain the fail-closed preflight. The README and CODEX runbook now require a launchd-origin check of the exact installed helper and name the macOS 27.2 settings categories.
- **Verification:** Installer completed from exact merged main; the installed CLI, helper, and Monitor signatures validated; the Monitor and daemon restarted while the official ChatGPT PID stayed unchanged. Interactive window inventory succeeded, and the launchd inventory reproducibly returned `WINDOW_ACCESSIBILITY_DENIED`. No cold-task or multiwindow recovery was claimed.
- **Prevention/follow-up:** After explicit authorization, refresh the current binaries' Device Control and Screen Recording grants, then rerun the same launchd inventory. Do not infer Screen Recording status while Accessibility is denied. Recheck after every ad hoc rebuild; use a stable signed identity when one is available and independently test grant retention.
- **Reusable learning:** A visible privacy toggle and a Terminal probe cannot replace a check from the exact background process after a rebuild.
- **References:** PR #49, `scripts/codex-window-restore.swift`, `codex-switcher/src/distribution/distribution_checkpoint_service.rs`, [the earlier signature finding](2026-09-28-window-helper-itself-needs-stable-signature.md).

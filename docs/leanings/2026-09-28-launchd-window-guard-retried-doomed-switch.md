# 2026-09-28 — The shutdown window guard needs Accessibility, and the daemon retried the doomed switch every tick

- **Status:** Partial
- **Task/context:** The `cxi daemon` LaunchAgent attempted one automatic distribution (`trigger=auto reason=business_priority_return`) 21 times in 47 minutes against one ChatGPT process, with window preservation disabled. Find the failing step, give it its own audit line, and stop retrying an identical doomed switch every tick. This follows [the launchd Accessibility learning](2026-09-24-launchd-accessibility-blocked-auto-switch.md) and [the WindowServer banner learning](2026-09-25-windowserver-banner-after-accessibility-bypass.md).
- **Unexpected observation or failure:** Each attempt logged `REQUEST`, `DECISION`, `LOCK`, `SHUTDOWN` ("Stopping Desktop app gracefully"), then 20–35 s later `WINDOW_CAPTURE_SKIPPED`, then about 5 s later `OUTCOME status=failed code=transaction_failed`, with no step naming the cause. The daemon's stderr showed `Error in daemon tick: WINDOW_ACCESS_FAILED` for each. Desktop was never signalled. `preserve_window_bounds_on_restart=false`, which the 2026-09-24 learning introduced so the daemon could switch without Accessibility, no longer achieved that.
- **Evidence:**
  - Code path: `DistributionDesktopSwitchService::run` logs `SHUTDOWN`, runs the thread and rollout scan, then `capture_window_bounds` (`WINDOW_CAPTURE_SKIPPED`), then `DistributionCheckpointService::prepare`, whose first step, before any journal write, is `preflight_shutdown_windows` → `DesktopShutdownWindowGuard::checked_snapshot` → the helper's `count-standard-windows`. The recovery preflight was ruled out because it logs its own `RECOVERY_PREFLIGHT_FAILED` line and prefixes its error. `prepare` returned the helper's bare code unchanged, which matches the bare `WINDOW_ACCESS_FAILED` on stderr.
  - `count-standard-windows` calls `standardWindowFrames` (Accessibility `kAXWindowsAttribute`) before `CGWindowListCopyWindowInfo`, and both map a failure to `WINDOW_ACCESS_FAILED`. The switcher log had no `RECOVERY_BANNER_UNAVAILABLE: WindowServer capture failed` line in the window. So the WindowServer-only `capture-banner-window` read succeeded in the same attempts, and the WindowServer read was not the failing call.
  - A throwaway probe binary run interactively reported `AXIsProcessTrusted()=true` and a `kAXWindowsAttribute` status of `0`. The same binary as a one-shot `launchctl submit` job reported `AXIsProcessTrusted()=false` and status `-25211` (`kAXErrorAPIDisabled`). `CGWindowListCopyWindowInfo` returned a list in both contexts, and `CGPreflightScreenCaptureAccess()` was `true` interactively but `false` under launchd. The probe read Finder, because ChatGPT was not running during the investigation, so the probe's target was not the ChatGPT process.
  - `arm_automation_cooldown` runs only after the recovery preflight, so a failure in `prepare` armed no cooldown. Every tick, or every watchdog wake while the active account looked depleted, repeated the full scan.
  - Adversarial review found an adjacent bug in `prepare`. When `RecoveryManifestSnapshot::capture` failed, `prepare` returned without clearing the `stopping_desktop` distribution journal, although Desktop had not been signalled. The journal gate then deferred later attempts as in flight for 300 s. After that it failed every tick with a stale, uncertain journal, because stale cleanup accepts only `initialized`. A switch-service test that turns the checkpoint into a directory reproduced it.
- **Approaches tried:**
  - **Attempt:** Suspect `CGWindowListCopyWindowInfo` returning nil in the LaunchAgent.
    - **Outcome:** Did not work.
    - **Why:** The banner capture used the same API successfully in these attempts, and the launchd probe read the window list. The failing read is the Accessibility half of the guard.
  - **Attempt:** Skip the multi-window guard when preservation is disabled.
    - **Outcome:** Rejected.
    - **Why:** AGENTS.md requires the guard in both modes. A restart reopens one window without its task, so an unverified window count must block the restart.
  - **Attempt:** Reuse the persistent automation cooldown for pre-signal failures.
    - **Outcome:** Rejected.
    - **Why:** It is a fixed delay that does not distinguish one failure from another. It would also delay a different, more urgent cause such as `quota_exhausted` for the same length of time.
  - **Attempt:** Persist the backoff in a new `~/.codex` state file so the `codex` wrapper's preflight also sees it.
    - **Outcome:** Rejected for now.
    - **Why:** A new Monitor writer needs the exact-name uninstall list, staging rules, and shell-test coverage. The reported loop is the daemon's, and an in-memory record that a daemon restart resets is enough for it.
  - **Attempt:** Return a typed `DistributionTransactionError` that names the pre-signal audit phase, log `SHUTDOWN_WINDOW_GUARD_FAILED` (or `RECOVERY_CHECKPOINT_FAILED`) from the switch service, and give the daemon an in-memory `AutomaticDistributionBackoff` keyed by reason, current and target accounts, phase, and message.
    - **Outcome:** Worked in tests.
    - **Why:** The coordinator can tell a failure that left credentials and Desktop unchanged from one after the signal, and only the former can safely hold later automatic attempts back.
- **Root cause:** The multi-window shutdown guard added for window-task restoration reads Accessibility regardless of `preserve_window_bounds_on_restart`. Under launchd, macOS attributes the helper's request to the job's executable (`~/.local/bin/cxi`), which has no Accessibility grant, so the guard always failed. The failure left no journal and armed no cooldown, so the daemon retried it at poll frequency.
- **Resolution:** `DistributionCheckpointService::prepare` returns a `DistributionPreSignalFailure` whose phase is always `SHUTDOWN_WINDOW_GUARD_FAILED` or `RECOVERY_CHECKPOINT_FAILED`, and it clears the unmodified journal when the checkpoint snapshot cannot be captured. The switch service logs that phase with "Desktop was not signalled", and the `OUTCOME` line appends `pre_signal_phase=<phase>` after `code=transaction_failed`. Window-capture, recovery-preflight, and before-signal shutdown failures are also typed as pre-signal. The daemon loop owns one `AutomaticDistributionBackoff`: after two consecutive identical pre-signal failures of the same automatic plan it logs `AUTO_BACKOFF_ARMED` and defers that plan (`AUTO_BACKOFF_ACTIVE`, status `deferred_cooldown`) for 5 minutes, doubling to at most 30. `AUTO_BACKOFF_ACTIVE` is logged once per hold, because the watchdog can wake the loop every two seconds. The streak ends after any other attempt result (success, or a failure after the signal), a different plan or failure (only the latest plan is kept), an hour without a failure, or a daemon restart. Manual requests never consult or change it. A hold pauses while the Mac sleeps (`Instant`), and a settings change does not lift it. README, CODEX.md, and AGENTS.md no longer claim that disabled preservation avoids Accessibility.
- **Verification:** `distribution_pre_signal_backoff.test.rs` and `automatic_distribution_backoff.test.rs` failed on no-op stubs (no guard phase line, no backoff) and pass with the change. `unreadable_checkpoint_clears_the_unsignalled_journal` failed on the retained journal before the fix. The coordinator tests also prove that a failure after the signal ends the streak, which a mutation that observes only pre-signal errors breaks, and that the journal gate and cooldown are checked before the backoff. Existing post-signal tests now assert that their `OUTCOME` has no `pre_signal_phase`, and the window-capture test asserts `pre_signal_phase=WINDOW_CAPTURE_FAILED`. They cover the guard's phase and outcome lines with Desktop unsignalled and credentials unchanged, arming after the second identical failure, deferral without a new attempt or `LOCK`, manual requests bypassing it without resetting it, another cause not being held, a changed failure restarting the count, doubling to the cap, expiry, and recovery from a poisoned lock. The checkpoint and switch-service tests now assert each pre-signal phase. The full `cargo test --locked` suite and the Clippy gate pass. Not verified live: the installed daemon, and whether granting Accessibility (and possibly Screen Recording) to `cxi` lets the guard pass.
- **Prevention/follow-up:** Grant `~/.local/bin/cxi` Accessibility and rerun an automatic switch from the LaunchAgent. If `WINDOW_INVENTORY_MISMATCH` follows, WindowServer is withholding titles without Screen Recording, and the guard needs a title-free identification or that grant as well. The `codex` wrapper preflight is still unthrottled. Give every new pre-signal failure a named phase.
- **Reusable learning:** A new Accessibility read added to a path the daemon runs undoes an earlier "works without Accessibility" guarantee, so re-probe from a real launchd job whenever a helper command gains an AX call. A retrying loop must be able to tell a failure that left everything unchanged from one that changed state, and it must back off on the first kind.
